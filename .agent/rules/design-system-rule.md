# design-system-rule.md — Build Rules: UI & Design System

Scope: everything a user sees — routes and components in /app, shared components, and the visible copy of notification templates.
Precedence: PRD (features) > AGENTS.md (process) > this file. If this file conflicts with either, follow them and flag the conflict.
Token source: the generated CSS tokens file, regenerated by the owner from Figma. It defines colour tokens (primitives and roles), spacing, shadows, and 15 whole-style `.typography-*` classes.
Every rule here is a failure condition. Cite DS-n in the Question 6 checklist when touched.

## Rules

**DS-1 The generated token file is untouchable.** Never edit it by hand: regeneration overwrites the edit without warning. A needed token or type-style change is fixed at the Figma source and regenerated by the owner. Stop and flag it; never work around it. Import the file once, globally, in the root layout.

**DS-2 One source, no copies.** Token values never appear in a second place: no Tailwind or theme config, JS/TS constants, or second stylesheet re-declaring them. Do not add a UI kit or CSS framework unless the owner adds it to the stack lock (AGENTS Q2); if one is ever added, it consumes these variables and classes and never redefines them.

**DS-3 Roles only.** Component CSS uses `--color-role-*`. `--primitive-*` variables never appear outside the generated file, even though the roles alias them. No hex, rgb, or hsl literals in component code.

**DS-4 Exact names, verified.** Use token names exactly as generated, misspellings included: `--spacing-extra-extra-samll`, `--color-role-surface-varaint`, `--color-role-on-surface-varaint`. Zero spacing is `--spacing-no`, not `--spacing-none`. Do not correct names locally or create aliases. If the owner fixes a name at source, every usage changes in the same change. Before completing any task, confirm every `var(--…)` you wrote exists in the generated file (an unknown variable fails silently). Tokens ending in `-2` (`--color-role-surface-container-lowest-2`, `--color-role-inverse-on-surface-2`) have no documented purpose: do not use them until the owner names their role.

**DS-5 Spacing and effects from tokens only.** Every margin, padding, and gap uses `--spacing-*`. Every box-shadow uses `--effect-hard-shadow`, `--effect-medium-shadow`, or `--effect-soft-shadow`. No literal lengths for spacing (0 or `--spacing-no` excepted).

**DS-6 Type styles are applied as whole classes.** The 15 classes are `.typography-{display|headline|title|body|label}-{large|medium|small}`. Apply one by `className`. Never set `font-family`, `font-size`, `font-weight`, `line-height`, or `letter-spacing` in component code, never override a class, and never rebuild a style from parts. A size or weight not among the 15 does not exist: flag it, do not invent it. The classes set no colour; colour comes from role tokens. Do not write your own copies of these classes, and note that CSS Modules would hide them — the classes are global.

**DS-7 Fonts must resolve by exact name.** The classes name `'Lora'` (Display styles only) and `'DM Sans'` (everything else). Load Lora 600 and DM Sans 400, 500, and 600, once, in the root layout, so those exact family names resolve — Google Fonts stylesheet link, or self-hosted `@font-face` declaring those names. `next/font` generates renamed families and will NOT satisfy the classes as they are: do not use it, and do not edit the classes to match it; flag it to the owner instead. No other typefaces. Confirm in the browser that headings render in Lora and body text in DM Sans, not the fallback.

**DS-8 Contrast is a hard gate.** Text and informational icons must reach 4.5:1 (WCAG AA, normal text). These pairings in the token file do not, so they are never used for text or icons:

| Pairing | Ratio |
|---|---|
| on-secondary on secondary | 2.12 |
| on-tertiary on tertiary | 2.02 |
| on-success on success | 2.29 |
| on-warning on warning | 3.38 |
| on-primary-container on primary-container | 3.37 |
| on-secondary-container on secondary-container | 3.37 |
| on-tertiary-container on tertiary-container | 3.23 |
| on-success-container on success-container | 3.54 |
| secondary, success, or warning roles used as text/icon colour on surface | 2.03 / 2.19 / 3.24 |

[ASSUMPTION — interim until the owner fixes these at source] On those fills and containers, use `--color-role-on-surface` for text (5.1:1 or better in every case) and carry the hue in the fill or a shape. All other role pairs pass and are used as generated: primary, neutral, neutral-variant, error, info, the warning container, surface, and inverse surface. Do not "fix" contrast by darkening a token locally (DS-1, DS-2).

**DS-9 Token gaps are flagged, never filled.** The token set has none for: border-radius, border width or colour (no outline role), disabled state, focus ring, overlay/scrim, motion, z-index, breakpoints, icon size, or dark mode. Never invent these. Use none/0/the browser default, keep the browser's default focus indicator (never `outline: none` without an equal replacement), add no `prefers-color-scheme` overrides, and list each gap you hit under the Question 7 open items so the owner can add it in Figma.

**DS-10 Component placement.** [ASSUMPTION] Shared presentational components live in /components (not in the AGENTS tree yet). They contain no data access and no permission decisions. Route-specific components stay inside their route group: (seeker), (provider), (reviewer), (admin).

**DS-11 One mapping per status enum, never colour alone.** Each enum below renders through one exhaustive mapping (label + container role). No inline status-to-colour ternaries. The label text always appears with the colour (text per DS-8).

| Enum | Mapping [ASSUMPTION — owner to confirm] |
|---|---|
| VerificationStatus | PENDING warning · APPROVED success · REJECTED error |
| AffiliationStatus | PENDING warning · ACCEPTED success · REJECTED error |
| ListingStatus | DRAFT neutral · PENDING_REVIEW warning · ACTIVE success · SUSPENDED error |
| BookingStatus | SCHEDULED info · COMPLETED success · CANCELLED neutral · AGENT_NO_SHOW error · LISTING_MISREPRESENTED error |
| ReviewCaseStatus | OPEN warning · UNDER_REVIEW info · RESOLVED neutral |
| SubscriptionTier | FREE neutral · AGENCY_PRO primary |
| hasOpenReports flag | warning (never error — see DS-13) |

**DS-12 Two gates, two signals.** Account verification and listing approval are different badges with different wording. Never a single "Verified" badge that implies the property itself was checked. Badges render from server-provided status and are never derived in the client. A verified-account signal never appears for a PENDING or REJECTED account.

**DS-13 Report and flag visibility (PR-REP-001, PR-LST-003).**
- A report control is present on every listing view and every agent/agency/landlord profile view, with a required reason field.
- Anonymous viewers are sent to sign-in; non-seeker roles get no submit path (PRD: authenticated SEEKER only).
- The `hasOpenReports` flag is visible to any viewer on every surface that shows the listing (card, detail, results), and the listing stays in results.
- A report is an allegation, not a finding: the flag uses the warning role, never error.

**DS-14 Rejection explains itself (PR-VER-004).** The applicant sees the reviewNote and a resubmit path — never a bare "Rejected". The reviewer's reject form cannot submit without a note (mirroring the server rule, which remains the authority).

**DS-15 The server is the authority.** UI hides or disables controls for convenience only, driven by capabilities computed server-side. Components contain no role or status permission logic of their own. A 403 renders an explicit "not permitted" state, never an empty list, blank page, or "no results".

**DS-16 No optimistic success for guarded actions.** Booking a slot, submitting a report, verification and listing decisions, and subscription upgrades show success only after server confirmation. A rejected double-booking shows "slot no longer available" and refreshes availability. After checkout, show "payment received, activating" until the webhook-confirmed state arrives (MB-5, MB-6).

**DS-17 Money display goes through one formatting function** taking integer minor units plus currency. No inline `price / 100`, no float math. The currency is always shown with the amount.

**DS-18 No false assurances.** Copy never states or implies that Domora guarantees a listing, agent, or transaction, or that Domora holds, protects, or escrows rent or deposit money ("guaranteed", "100% safe", "protected payment", "escrow"). Status wording is factual: what was reviewed, not what is promised.

**DS-19 Sensitive data is role-scoped.**
- Verification documents appear only in the applicant's own view and the reviewer console.
- ReviewCase details and reporter identity appear only in the reviewer console; the reported account never sees who reported it.
- Reviewer and admin UI is never served from the seeker or provider route groups.

**DS-20 Accessibility floor.** Every input has a programmatic label. Every interactive element is keyboard-operable with a visible focus indicator. Error messages are associated with their fields.
